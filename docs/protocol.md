# SSE framing

Decoder accepts LF, CRLF, or CR; strips one leading UTF-8 BOM; ignores comments, retry and unknown fields; splits at the first colon; removes at most one leading value space. Multiple data fields join with newline and dispatch at a blank line. A data field with an empty value dispatches empty data. Empty/comment-only blocks never dispatch. Event names default to message and reset per block. IDs persist across events, reset with empty id, and ignore values containing NUL. Payload JSON is never interpreted.

The parser consumes bytes, so read boundaries and split multibyte UTF-8 do not determine events. A completed line is validated strictly: invalid UTF-8 produces INVALID_UTF8 instead of WHATWG replacement characters. EOF never dispatches a pending event; any unfinished block (including comments without a final blank line) yields INCOMPLETE_FRAME. Invalid final UTF-8 takes precedence. These deliberate strict diagnostic choices differ from a permissive browser EventSource.

Default frame cap: 1 MiB; CLI configurable up to 16 MiB. The cap includes all fields/comments between blank lines. CRLF counts as one normalized line-ending byte for parser/frame accounting; `totalBytes` counts every actual body byte. A BOM counts toward the cap. A CR completes a line immediately; the following LF is ignored. The parser never buffers a whole HTTP body and returns at most one event per input byte. Individual ignored fields/comments are bounded too. A persistent last-event ID is capped by the same frame bound. No automatic retry/reconnect is implemented.

Completed-event time is when sufficient bytes have been observed to complete a dispatch. Events within the same transport read may have identical timestamps. First byte/event offsets start before connecting; headers have a separate observed offset. Neither packet arrival nor server execution timing is claimed. Proxy buffering, OS scheduling, HTTP/2 multiplexing and TLS affect observations. Strict parser failures are distinct from network EOF/read failures.
